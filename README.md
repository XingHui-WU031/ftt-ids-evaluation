# False-alarm control and explanation reliability of feature-token Transformers for network intrusion detection

Code, configurations, per-run predictions and result tables for the manuscript

> X. Wu. *False-Alarm Control and Explanation Reliability of Feature-Token Transformers for Network
> Intrusion Detection under Dataset Shift.* Submitted to *Sensors*, 2026.

Every number in the manuscript can be regenerated in two ways: (a) from the saved predictions in
this repository, in a few minutes on a CPU, or (b) from scratch, by retraining all models
(roughly one day of GPU time on the hardware listed below).

## Repository layout

| Path | Contents |
|---|---|
| `run.py` | Single entry point: `check`, `tune`, `train`, `aggregate`, `explain`, `explain_r3`, `search`, `sensitivity`, `profile` |
| `src/` | Data protocol (`data.py`), models (`models.py`), training (`trainers.py`), metrics and threshold rules (`metrics.py`), aggregation and significance tests (`aggregate.py`), explanations (`explain.py`, `explain_r3.py`), random search (`search.py`) |
| `scripts/` | Windows batch files that run the experiment rounds in order (`2_…` to `5_…`) |
| `results/` | Rounds 1–2: validation grids (`tuning/`), per-run `metrics.json`, `preds.npz` and training histories (`runs/`), summary tables (`tables/`), SHAP summaries (`explain/`) |
| `results_r3/` | Round 3: no-dedup control, host-disjoint TON_IoT, Integrated Gradients, retraining-based faithfulness, random search |
| `analysis/` | Scripts that recompute the manuscript tables from the saved predictions (see below) |
| `manuscript_source/` | Manuscript text and the scripts that draw the figures and build the Word files (provided for reference; their paths point to the author's working directories) |

Model weights are not included; they are regenerated by training. The raw datasets are not
redistributed.

## Environment

Python 3.13. Exact package versions are pinned in `requirements.txt`
(PyTorch 2.11.0 with CUDA 12.8, scikit-learn 1.9.0, XGBoost 3.4.1, SHAP 0.52.0).

```
python -m venv .venv
.venv\Scripts\activate            # Linux/macOS: source .venv/bin/activate
pip install torch==2.11.0 --index-url https://download.pytorch.org/whl/cu128
pip install -r requirements.txt
python run.py check                # prints library versions and the GPU
```

Hardware used: NVIDIA GeForce RTX 5060 Laptop GPU (8 GB), Windows. All experiments also run on
a CPU (`--cpu`), only more slowly.

## Data

| Dataset | Files | Source |
|---|---|---|
| UNSW-NB15 | `UNSW_NB15_training-set.csv`, `UNSW_NB15_testing-set.csv` | https://research.unsw.edu.au/projects/unsw-nb15-dataset |
| TON_IoT | `Train_Test_Network.csv` | https://research.unsw.edu.au/projects/toniot-datasets |

Put the UNSW-NB15 files in one folder and the TON_IoT file in another, and pass the folder with
`--data-dir`. Without `--data-dir`, `run.py` looks in `../数据集/` and `../数据集/TON_IoT/`.

## (a) Recompute the tables from the saved predictions

```
cd analysis
python 00_prepare_unsw_labels.py <folder with the UNSW-NB15 csv files>   # rebuilds the split, saves labels
python 01_budget_sweep_matched_fpr_recalibration.py    # Tables 4, 8, 10; Figure 5; calibration; sub-population decomposition
python 02_verify_manuscript_numbers.py                 # Table 9; false-alarm composition; TTL-free overlap
python 03_paired_tests_bootstrap1000.py                # Table 5 (McNemar, paired bootstrap, 1000 replicates)
python 04_round3_nodedup_and_host_disjoint.py          # Tables 11 and 13; Figure 6
python 05_round3_roar_and_integrated_gradients.py      # Tables 15 and 16
python 06_round3_random_search.py                      # random-search comparison (Section 4.1)
```

Outputs are printed and written to `analysis/out/`. Tables 3, 6, 7 and 12 are the summary tables in
`results/tables/<dataset>/`; Table 14 is in `results/explain/<dataset>/proposed/summary.json`.

## (b) Retrain everything

```
python run.py tune      --dataset unsw      --data-dir <UNSW folder>
python run.py train     --dataset unsw      --group main      --data-dir <UNSW folder>
python run.py train     --dataset unsw      --group ablation  --data-dir <UNSW folder>
python run.py aggregate --dataset unsw      --data-dir <UNSW folder>
python run.py explain   --dataset unsw      --model proposed  --data-dir <UNSW folder>
```

`scripts/2_run_unsw_experiments.bat`, `3_followup_unsw.bat`, `4_run_toniot_experiments.bat` and
`5_run_round3.bat` contain the complete command sequence. Finished runs are skipped, so an
interrupted script can simply be started again.

Dataset names accepted by `--dataset`:

| Name | Meaning |
|---|---|
| `unsw` | UNSW-NB15, duplicates removed before the 80/20 training–validation split |
| `unsw_nodedup` | control without duplicate removal |
| `unsw_noshortcut`, `unsw_nottl` | without `sttl` and `ct_state_ttl`; without all three TTL features |
| `unsw_roar_top5`, `unsw_roar_top10`, `unsw_roar_rnd5a/b`, `unsw_roar_rnd10a/b` | retraining-based faithfulness (feature sets are listed in `src/data.py`) |
| `toniot` | TON_IoT, random 60/20/20 split |
| `toniot_host0` … `toniot_host4` | TON_IoT, host-disjoint folds (stratified group five-fold split on the source address) |

## Determinism

The data split uses seed 42 throughout. Training seeds are 42–46 (42–44 for the host-disjoint and
retraining experiments). Seeds fix parameter initialisation and mini-batch order; results on a
different GPU or library version can differ in the last digits. XGBoost was trained on the GPU
(`device="cuda"`); CPU training gives slightly different trees.

## File formats

- `runs/<dataset>/<model>/seed<k>/preds.npz`: `p_val`, `p_test` (attack probabilities)
- `runs/<dataset>/<model>/seed<k>/metrics.json`: validation and test metrics for every threshold rule, per-category detection rates, training configuration
- `runs/<dataset>/meta.npz` (round 3): `y_val`, `y_test`, `g_test` (attack type) and, for host-disjoint folds, `host_test`
- `runs/<dataset>/y_test.npy`: test labels
